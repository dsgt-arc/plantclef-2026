## LoRA discussion (before P2 launch)

User asked about LoRA as P2 alternative. Rejected for this setting:

- Published evidence: LoRA trails full-FT by 1–3 pts on fine-grained vision with ≥100K training images (arXiv:2203.12119, 2210.08823, 2402.02242).
- No PlantCLEF precedent.
- Resource savings at 518² are marginal (activations dominate memory, ~87% of footprint; LoRA saves only optimizer state + grads).
- Ensemble diversity argument cuts against LoRA (frozen trunk → error correlation with Phase-1 baseline).
- Decision: full-FT Phase 2 with hybrid PlantNet/MAE recipe.

Visualizations produced in `docs/viz/`: `decision_matrix.md`, `param_budget_diagram.md`, `memory_breakdown.md`.

## Counterfactual: aggressive from E0?

Discussed whether aggressive recipe from the start of P2 would have been better. Conclusion:

- **Slightly better best-case** (~+0.3 to +0.5 pt at matched epoch, saves 5–10 epochs) if it didn't diverge.
- **Real divergence risk** — `lr=8e-5` + `layer_decay=0.85` + 2-epoch warmup on a freshly-unfrozen backbone (P1 frozen for 65 epochs) is a known instability pattern.
- The v1 → v2 sequence works as "risk-managed bootstrap": v1's conservative 20 epochs safely adapted the backbone, v2's aggressive restart pushed the ceiling.
- **Ceiling (~77.5–78) is set by architecture + data, not optimizer trajectory.** Both paths converge to similar endpoints.
- For future experiments: an intermediate recipe (lr=7e-5, layer_decay=0.80, warmup=3) from E0 would capture most upside with less risk. But the two-stage approach is approximately optimal given uncertainty.
